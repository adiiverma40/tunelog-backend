# Listenbrainz

This docs contains everything about how listenbrainz is used in this project. It is not type specific, meaning, if listenbrainz is used in either playlist gen or fetching `LB_CF` everything will be here

## LB CF

Listenbrainz Collaborative Filtering is used to generate playlist based on the user's listening history and is generated by listenbrainz.

The architeture is as follow:

- User logs in
- He navigates to Listenbrainz playlist under playlist section.
- There is an option to enter the listenbrainz token, After listenbrainz token is entered.
- The backend uses cryptography to encrypt the token and save in the database.
- After that, the backend uses the token to ping listenbrainz and fetch username of the entered token
- After that, It fetches CF data from listenbrainz adn saves it in database..

## Playlist Generation

Right now, the playlist generation works with a index in mind.

**Config:**

```json
{
  "cf_playlist_config": {
    "size": 100,
    "heard": 50,
    "unheard": 50,
    "unheard_genre_injection": true,
    "heard_genre_injection": false,
    "unheard_last_score": 0.4249504506587982,
    "heard_last_score": 0.6684868931770325,
    "auto_generate_time": 1,
    "Name": "Listenbrainz Playlist",
    "backfill_unheard_song": true,
    "use_blend": true,
    "last_score": 0,
    "fallbackScore": true,
    "for_users": ["adii"],
    "last_generated": 1787205915
  }
}
```

Listenbrainz returns the cf with a score for each song. ranging from 0 to 1. `unheard_last_score` and `heard_last_score` are the last scores for unheard and heard songs respectively.
Imagine it like a cursor, the cursor moves down systemtically. and then save it in config file.
